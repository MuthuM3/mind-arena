# Mind Arena Product Execution Program

**Status:** Active scope ledger

**Program reset:** 2026-07-29

**Current milestone:** M1 — Today’s Arena experience proof

## Program objective

Prove that one story-driven shared arena can combine emotion, meaningful choice, and surprising real
human perspective, then grow through Friend, Live, and Purpose Arenas using the same engine only
when evidence, community density, and safety permit.

## Source-of-truth order

1. Human product owner decisions
2. `AGENTS.md`
3. Product vision
4. V1 PRD
5. This execution program
6. Product-system, architecture, safety, and operating documents
7. Individual task packets

## Delivery strategy

- Validate the human interaction manually before automating it.
- Start inside dense trusted communities, not a global empty network.
- Build supply, moderation, and trust as product features.
- Ship one complete story-driven arena before a content catalog.
- Preserve the Arena Engine domain grammar without building speculative formats.
- Measure insight and reciprocity, not time spent.
- Keep synchronous/live work behind an evidence gate.
- One founder chooses one vertical slice at a time.

## M1 — Today’s Arena experience proof

### Goal

Demonstrate that Mars Rescue creates curiosity, a meaningful choice, a surprising real human
perspective, and a memorable three-minute Mind Shift.

### Work packages

#### M1.1 Mars Rescue arena package

- finalize premise, roles, constraints, and decision;
- map at least five defensible reasoning families;
- define deterministic consequence rules;
- write safe examples for Build, Challenge, and Question;
- define editorial fallback cards;
- define spoiler-safe result-card fields;
- review cultural/accessibility assumptions.

#### M1.2 Six-scene storyboard

1. Today’s Arena invitation;
2. situation reveal and private choice;
3. contribution consent;
4. other human minds;
5. structured response and consequence;
6. final choice, Mind Shift, and share card.

Include reduced-motion, empty-pool, unsafe-content, and withdrawal states.

#### M1.3 Manual prototype

- simple tappable adaptive UI for phone, tablet, and desktop;
- local fixture repository behind production-shaped domain interfaces;
- compact, medium, and expanded layout plus keyboard/focus checks;
- first usable-frame and interaction-response measurements;
- researcher-operated perspective pool;
- manual matching and moderation;
- manual consequence and Mind Shift template;
- observation and consent materials.

#### M1.4 Stage 0 and Stage 1 research

- recruit 8–10 concept participants;
- revise language;
- recruit 12–20 exchange participants;
- run repeated manual sprints;
- synthesize behavior and decision.

### Exit criteria

Meet or consciously revise the Stage 1 gates in the validation plan. If real human difference does
not produce distinct value, stop before backend work.

## M2 — Concierge network

### Goal

Prove repeated asynchronous arenas, perspective supply, consent, comparison, and reciprocity.

### Work packages

- two to three arena packages using the same engine grammar;
- controlled cohort invitations;
- lightweight identity and arena aliases;
- contribution/withdrawal workflow;
- founder moderation console;
- response-ready notifications;
- manual pool-health dashboard;
- second-arena behavior study;
- moderation policy draft.

This can use low-code/manual operations. It is a product experiment, not the production stack.

### Exit criteria

- repeated arenas retain enough safe perspective supply;
- people return without direct founder prompting;
- contributors value receiving responses;
- moderation workload and risks are understood;
- the async format is honestly understood and still useful.

## M4 — AI-assisted beta

### Goal

Add AI only where it measurably improves human interaction or operational feasibility.

### Slices

1. versioned evaluation harness;
2. moderation triage;
3. optional respectful rewrite;
4. reasoning representation for selection;
5. facilitation move recommendation;
6. traceable Mind Shift draft;
7. provider fallback, cost, and rollback;
8. controlled experiments against deterministic/manual baselines.

### Exit criteria

- AI improves a defined human or operational measure;
- provenance and faithfulness pass audit;
- safety does not regress;
- provider failure does not block exchange;
- cost per MPE is known;
- manual rollback remains possible.

## M5 — V1 hardening

### Goal

Operate a reliable, accessible, trustworthy invited beta across several communities.

### Deliverables

- three to five proven arenas using the same engine;
- finalized core moderation policy;
- reviewer/support tooling;
- data export/deletion;
- notification preferences;
- supported-device matrix;
- security/privacy review;
- operational dashboards without raw content;
- incident, backup, and recovery drills;
- store distribution preparation if justified;
- beta onboarding and community playbook.

### Exit criteria

- no open P0/P1 issue;
- privacy and human/AI labels match implementation;
- cohort growth does not degrade safety or perspective quality;
- repeat behavior supports a broader launch;
- support capacity matches cohort size.

## M6 — Expansion discovery

Choose one, not both.

### Option A: Friend Arena

- invite to the same arena;
- hidden independent choices;
- delayed reveal;
- comparison and response;
- organic invitation loop.

### Option B: Live Arena

- concierge groups of three to five;
- multi-round turn grammar;
- dropout/reconnect behavior;
- real-time moderation;
- WebSocket technical spike only after format validation.

### Option C: Purpose Arena

- invite-based brainstorming or decision room;
- host-defined question;
- private workspace;
- shared synthesis;
- retention and administrator boundaries.

### Decision rule

Choose the path with stronger recurring user pull, safe operating model, and defensibility. Do not
select Friend merely because it appears viral, Live merely because it is visually exciting, or
Purpose merely because companies can pay.
